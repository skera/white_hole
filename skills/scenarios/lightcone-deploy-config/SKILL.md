# Lightcone 配置发布

沿用用户确认的服务/实验、环境、目标参数名称/类型/值、保存或发布范围、并发、验收与通知要求。只读查询止于目标和状态核对；仅保存任务完成步骤3后结束。镜像/bin 升级使用 [caster-release](../caster-release/SKILL.md)，不把“新配置发布”当作镜像发布。

读取 [Lightcone 界面](../../platforms/lightcone-platform/SKILL.md)；执行时读取 [操作与完整配置校验](references/workflow.md)，遇加载、审批、截图或指标矛盾时读取 [问题处理表](references/troubleshooting.md)，采集及验收前读取 [监控方法](references/monitoring.md)。场景规则由本技能负责，浏览器操作和原始监控查询由依赖技能执行。

## 依赖与执行前检查

| 依赖 | 用途与加载时机 | 安装位置 / 来源 |
| --- | --- | --- |
| `lightcone-platform` | 必需；执行前读取平台结构 | 本仓库相对链接，随仓库分发，保持目录关系 |
| `ego-browser` | 浏览器操作前读取当前技能及其 CLI 使用说明 | 当前运行环境已安装的技能；缺失时从已确认的官方来源安装 |
| `davinci-tool:promql` 或已授权的等价范围查询工具 | 需要监控时查询原始数据；分析规则属于本场景 | 当前环境的 davinci-tool 插件或既有工具，不能猜测下载地址 |
| 当前授权的通知工具 | 仅在用户要求通知时需要 | 可复用现有工具或 webhook 脚本，不强制安装额外消息技能 |

依赖名称和必要性在此声明，详细调用方法读取对应依赖，避免复制其说明。相对链接表示文档依赖，不会自动安装技能；仓库路由使用与运行环境技能安装是两件事。安装场景时一并检查依赖，保持相对路径或适配路径；不要假设运行环境递归发现嵌套技能。

首次执行前检查本次所需依赖是否存在、可调用及已认证。发布任务的浏览器、监控和必需通知能力应在修改配置前就绪，不能发布后才发现无法验收。仅保存任务不要求安装监控能力。缺失时先核实可信安装源和当前授权，允许独立只读检查；安装完成后验证可调用性，再执行依赖它的阶段。日常执行只检查，不反复安装或自动升级。安装不授予生产发布、登录或外部通知权限；本 skill 不包含自动依赖安装器。

## 1. 定位与筛选目标

- **操作**：搜索服务 → 点击左侧精确服务结果 → 等待详情刷新 → 指定实验 e → 配置。不能只输入搜索词就沿用右侧旧详情；等待异步配置响应业务成功，核对页面与响应。
- **核对**：服务标题、服务树、实验、服务/实验 ID、app 前缀、环境与配置模型对齐；遍历分页，以服务 ID + 实验 ID + 环境去重。区分一个实验与其 CPU/GPU app，记录实际部署侧。
- **筛选**：本补旗任务中，GPU **线上已发布**目标 flag 且类型/值正确则整实验跳过，CPU 暂不补；草稿有值不算已发布。GPU-only 只改 GPU，不创建 CPU 配置；新任务明确双侧要求时遵从新范围。
- **无模型**：可靠成功响应及发布/实例证据共同支持时才跳过。Caster app/link、zone 与实例数表明曾初始化发布；0/0、0 QPS、puregpu 名称和暂空表单都不是无模型证据，冲突保持未知。

## 2. 检查流程、允许差异与基线

- **操作**：检查本次在途记录及审批；复用本次已触发发布的剩余检查，不覆盖他人流程。保存线上配置 O、修改前草稿 D0、发布标识、实例状态及逐 pod 基线。
- **核对**：比较 O → D0，列出既有待发布差异。建立允许集合：目标参数、必要“配置galaxy”开关及本次明确批准的额外变化。历史默认字段补齐或恢复线上值的授权不能自动沿用到新任务。
- **门禁**：范围、允许差异、监控口径及本次适用豁免已明确。基线时间窗沿用约定，历史约10分钟只是参考；等待过久后补取，避免把提交前变化归因于本次发布。

## 3. 编辑、保存与读回

- **操作**：GPU部署配置 → 配置galaxy → 额外gflags；CPU+GPU 实验按目标处理 CPU。填入名称、类型和值，保存 → 核对保存 diff → 确认 → 读回保存后配置 D1。
- **核对**：写入前草稿仍为 D0；同名同类型同值不重复添加。仅新增任务遇已有不同值报告冲突，不能擅自覆盖。比较 D0 → D1，原有字段、组包大小、线程数和资源配置不得出现未授权变化。
- **门禁**：按操作参考做完整结构化比较，UI diff 不能覆盖未展示的默认字段。意外变化停止该实验并列出旧值 → 新值；不擅自恢复他人草稿。仅保存时报告持久化证据，不触发发布。

## 4. 核对发布 diff 并提交

- **操作**：新配置发布 → 等待真实发布 diff → 核对 O → D1 全部差异 → 确认 → 开始。记录当前发布 ID/链接、提交时间及已触发证据。
- **核对**：提交前重读线上版本与草稿，仍与已审核 O、D1 一致；重新检查暂停状态、目标映射和真实在途数量。接口没有原子版本条件时说明并发修改限制。
- **截图**：按要求保存真实完整 diff，检查实验、前后方向及内部滚动区；长内容分图，不以普通配置页或重绘 JSON 冒充。图片与完整配置检查分别保留。
- **门禁**：已有发布授权且完整差异通过才提交。额外差异阻塞该实验；其他独立目标可按授权继续。旧单驳回但仍审批中不算终止，不代批或废弃他人流程；负责人处理后核对锁和最新 diff。结果不明先查记录，不重复提交。

## 5. 确认平台完成与首批更新

- **平台**：等待本次发布记录整体终态；“配置更新触发成功”与中间步骤“执行成功”不算完成。已实证完成标志为“配置部署检查完成，最终状态: 执行成功”；页面版本变化时核实等价整体状态。
- **实例**：平台完成后跟踪调度滚动，记录首批 pod 的模型/配置版本、加载或启动时间、运行及接流状态。镜像 tag、Pod 名称或 QPS 低谷不能单独证明配置生效。
- **范围**：本补旗流程只验首批1–2个恢复 pod，不等全量切换；若另有全量要求，再跟踪全部目标。平台完成、配置实例生效、业务验收独立记录。

## 6. 验收首批

- **采样**：优先直接 PromQL 范围查询；使用本次已确认 source_id 和真实 app/cmd。固定本轮公共 start/end、step、rate/lookback、数据延迟；保存表达式和原始时序。定义不明时才查面板，不能互换 Lightcone server_id、Grafana datasource UID 与 Hawkeye source_id。
- **窗口**：沿用约定及实际采集周期，纳入样本的 rate/lookback 区间完整位于目标 pod 更新并恢复接流之后。不照搬 Caster 镜像升级的固定启动等待时长，也不以平台成功后固定几分钟判通过。
- **对照**：首批恢复 pod 与同一时刻仍接流的存量 pod、同打分头比较。记录版本依据和对照集合；只有QPS中断/恢复时标“更新候选，版本未核实”。历史基线只辅助解释，不能替代同期验收。

| 检查项 | 指标与判定 |
| --- | --- |
| 样本覆盖 | 目标/对照 pod 数、期望与实际点数、新鲜度、缺失、NaN/Inf、零分母；旧末值和跨恢复窗口不能证明正常 |
| 服务运行 | 逐 pod QPS 下降与恢复，按应用已确认定义补充错误率/延迟；整体总量不能掩盖局部未恢复 |
| 打分 | 每个 name 的同期原始值、均值、min/max、偏差与持续性；不把请求分布变化当作同请求不一致或 flag 因果 |
| 放行 | 按约定条件判断；无阈值时报告实际偏差与依据，不自造百分比 SLA。持续异常停止相关后续提交，不自动回滚 |
| 受限 | 单 pod/无有效存量对照标同期一致性未验证；真实零分一致不证明非零打分质量；缺版本证据不声称实例版本已生效 |
| 豁免 | 本次已授权且发布前无流量可豁免效果检查；有QPS仅缺打分则检查QPS并单列打分未验证。原有流量发布后消失不能套用豁免 |

首批满足条件即记录“首批验收通过，全量滚动未验收”；仅当另有全量要求且全部目标满足时记录全量通过。豁免、受限和通过分别报告，不因缺证据重复发布。

## 7. 并行、暂停与续跑

- **并行**：本补旗流程已授权最多3个实验在途；更低上限遵从用户，未确定并行范围则串行。实验间发布数与实验内滚动并发分别控制，不修改现有滚动策略。平台整体完成释放名额，监控继续，不把释放记为验收成功。
- **台账**：逐实验保存服务/实验 ID、环境、部署侧、页面、O/D0/D1、允许差异、发布 ID/链接、已执行动作、首批证据、最新状态、待办和通知回执；运行数据及凭据放仓库外。
- **暂停**：用户暂停即停止新增提交，已发起项继续跟踪；每次实际提交前检查暂停标记。停止自身动作不表示平台滚动已暂停，不自动暂停、回滚或恢复他人流程。
- **续跑**：用户明确恢复后先读台账再核对线上、草稿、他人修改和在途记录。会话丢失、超时或结果未知先查是否已触发；只执行未完成动作，不重放提交。

## 8. 进度与收尾

- 按本次授权渠道及频率提供服务/e/模型、目标变更、真实 diff、发布链接、采集时间和时区、平台状态、实例生效证据、监控窗口/覆盖/结论与缺口、下一步。未要求定时报告时不自行创建定时任务。
- 监控链接基于当前模板解析，替换实际 CPU/GPU 或 puregpu cmd/app/regex、环境、KFC/模型及数据源，保留重复参数。只保留实际存在的部署侧；不只替换 e 编号或猜测映射。
- 企业微信 Markdown 按渠道上限检查UTF-8字节数（群机器人通常4096字节）；按报告标识与回执防重，只有业务 `errcode=0` 记成功。结果未知先核对，不盲目重复；错误故障结论发送更正及最新截止时间。密钥留在仓库外，不写入报告。
- 最终按服务/实验去重汇总发布、跳过、阻塞、首批通过、受限及豁免数量。达到本次约定验收范围且最终报告送达后结束本任务监测；未送达或未验证项如实保留，停止自动化仅限本任务。全量滚动未验收不写成全量完成。
