# 基于 Caster 的发布（第二层，待实证）

读取依赖 [caster-platform](../../platforms/caster-platform/SKILL.md)。当前只有场景契约，没有 Caster 发布实证；平台层必须先补齐实际操作路径和状态语义，才能执行写入。

## 输入

应用/环境/集群、发布对象和目标版本/制品、范围及批次要求、发布授权、监控及验收窗口。任务未指定平台时不猜测为 Caster；涉及 Lightcone 联合发布时按根目录路由表选择联合场景。

## 编排

1. 调用平台只读识别目标、当前版本、目标制品、进行中的任务和实际发布路径；报告缺失前提。
2. 确认本次允许差异、目标实例/批次、健康验证与版本生效证据。依据实际支持能力处理灰度、分批和回滚，不能默认平台具备这些功能。
3. 获取发布前指标基线并记录部署前版本。若用户只要求准备变更，完成可审查结果后结束。
4. 在发布已授权、差异合格且执行路径已确认时，通过平台提交。记录任务标识和时间，等待实际部署终态。
5. 核对目标实例的实际版本和健康状况，再观察业务指标。状态成功但版本或监控证据不全时，结果标为部分验证。
6. 发布失败、持续异常或超时则停止后续批次并报告；不得默认重试或回滚。已有明确适用的恢复授权时才按平台实际支持路径执行。

## 输出

返回目标、旧/新版本或制品标识、差异、任务与时间、各批次/实例状态、业务指标及覆盖范围、未完成项。没有真实执行或证据时只报告“准备完成/待实证/受阻”，不得报告发布成功。
