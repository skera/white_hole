# 基于 Caster 的发布（第二层，待实证）

读取依赖 [caster-platform](../../platforms/caster-platform/SKILL.md)。当前只有场景契约，没有 Caster 发布实证；本场景先完成下述界面发现并形成可审查的 plan；缺少真实路径和状态语义时，不执行发布写入。

## 输入

应用/环境/集群、发布对象和目标版本/制品、范围及批次要求、发布授权、监控及验收窗口。任务未指定平台时不猜测为 Caster；涉及 Lightcone 联合发布时按根目录路由表选择联合场景。

## 编排

1. 先只读识别目标、当前版本、目标制品、进行中的任务和实际发布路径；报告缺失前提。
2. 确认本次允许差异、目标实例/批次、健康验证与版本生效证据。依据实际支持能力处理灰度、分批和回滚，不能默认平台具备这些功能。
3. 获取发布前指标基线并记录部署前版本。若用户只要求准备变更，完成可审查结果后结束。
4. 在发布已授权、差异合格且执行路径已确认时，按已验证的界面路径提交。记录任务标识和时间，等待实际部署终态。
5. 核对目标实例的实际版本和健康状况，再观察业务指标。状态成功但版本或监控证据不全时，结果标为部分验证。
6. 发布失败、持续异常或超时则停止后续批次并报告；不得默认重试或回滚。已有明确适用的恢复授权时才按平台实际支持路径执行。

## 输出

返回目标、旧/新版本或制品标识、差异、任务与时间、各批次/实例状态、业务指标及覆盖范围、未完成项。没有真实执行或证据时只报告“准备完成/待实证/受阻”，不得报告发布成功。

## Plan：补齐执行路径

使用当前环境的浏览器技能或已提供工具说明访问任务指定的 Caster 入口；需要登录时由用户完成。记录应用/环境/集群的唯一标识、当前与目标制品及实际发布入口，确认变更预览、批次策略、提交动作、任务状态和实例版本证据。平台不支持的能力不能写入计划。

将已确认的页面结构事实整理为第一层资料；本次动作顺序、输入输出、授权、停止条件和业务验收保留在本层。发现本身不能触发创建发布或回滚。用户只要求查询时，只执行计划的只读部分。

## Workflow 约束

目标版本已运行时避免重复发布；已有进行中任务先核实与本次目标关系。提交后跟踪本次任务，不能用历史成功记录替代；未知状态、失败或超出约定窗口时停止盲目重试并报告。草稿创建、正式发布和回滚按本次授权范围分别执行，不顺带恢复或发布其他变化。
