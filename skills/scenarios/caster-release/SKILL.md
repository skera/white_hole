# Caster 镜像发布

两种入口共用同一发布流程。沿用用户确认的范围、策略、并发、监控口径与通知要求；只读版本查询止于步骤1。浏览器操作遵循当前浏览器技能。

## 1. 定位目标

- **操作**：Caster 搜索完整 app；或 Lightcone 搜索服务后，点击左侧精确服务结果，等待详情刷新，再进入 e → CPU/GPU app → Caster链接。
- **核对**：服务标题、服务树、e、app 前缀、app ID、环境、zone 对齐；按 Pod 数和版本条件筛选，以 `app ID + 环境 + zone` 去重。
- **口径**：版本盘点读取已对齐的 Lightcone；实际运行镜像以 Caster 实例表为准，不把目标 tag 当作全量完成。

## 2. 检查流程与基线

- **操作**：检查在途流程；复用本次已有单，不覆盖他人流程。遍历全部实例分页，保存逐 Pod 镜像、启动时间、Running/healthy/up、实际数量及升级前监控。
- **核对**：实例表与摘要数量一致、健康接流；混合版本分别计数。原地升级不以 Pod 名称或名称中的发布号区分新旧。
- **记录**：每 app 独立保存发布单链接、首批/继续全部动作、监控窗口及结论；恢复时先读记录，再核对现场，防止重复操作。

## 3. 准备发布

- **操作**：目标 zone → 迭代发布 → 生产提醒“继续”；等待 app ID、实例数、镜像和策略加载。填写目标镜像、部署/滚动策略、并发、超时、自动暂停点、发布描述和回滚方案。
- **核对**：仅镜像升级时“生效新的应用配置”选“否”，不附带资源、容量、flags 或 Webhook 变更；检查镜像仓库与 tag。切换策略后重新读回并发等参数，防止被清空。
- **门禁**：无冲突流程、参数与授权一致、基线及业务监控可用，才提交。

## 4. 建单并启动首批

- **操作**：表单“发起流程” → 等待“预检配置正常” → 预检窗口“发起流程” → 审批通过或“无需审核” → “确认发布”。立即记录发布单 ID/链接并核对详情与 Diff。
- **启动**：`init` 仅为已建单。点击“继续” → 核对并发 → “继续批次”，确认 `deploying` 且实例开始更新，保存凭据。
- **门禁**：首批未验证，不点击“继续所有”；不代审批人操作。请求结果不明时先检查已有单和日志，不重复提交。

## 5. 验收首阶段

- **实例**：首批实际目标镜像、Running/healthy/up；记录启动及首次健康接流时间，平台倒计时结束。
- **采样**：优先直接 PromQL 范围查询。沿用已确认 source_id；缺失时按查询技能确认。固定本轮 start/end/step、rate窗口、数据延迟，保存表达式及原始时序；指标定义不明时再查面板。
- **窗口**：沿用约定；未指定时观察2min，各样本时刻启动至少5min且已健康接流。窗口起点及 rate/lookback 区间均不得跨重启或恢复边界；末点有修订时使用已确认的数据延迟。
- **对照**：同 Pod 升级前后 + 真实旧镜像同期、同打分头对比。保留的目标版本实例单列；首批原已为目标版本时仅算重启验证。排除已移除 Pod、旧末值及不成熟样本。

| 检查项 | 具体指标与判定 |
| --- | --- |
| 样本覆盖 | 当前 Pod 覆盖数、期望/实际点数、缺失、NaN/Inf、零分母；缺数据不得判通过 |
| 服务运行 | QPS、错误率、延迟；按应用实际定义查询，无流量不得判正常 |
| 打分业务（适用时） | 逐 Pod/逐头均值、min/max、离散程度、无效分计数或比例；明确单位和分母 |
| 版本差异 | 新旧同期相对偏差、同 Pod 前后变化及持续时间；检查单 Pod 异常，不以整体平均掩盖 |
| 放行条件 | 按约定阈值与持续性判定；未约定时报告实际偏差和依据，不编造阈值。摘要 N/A 或与实例表冲突、持续异常、覆盖缺失均不放行 |

监控统计不等于同请求逐条打分一致性。不同应用使用各自指标，不直接套用其他服务的查询。

## 6. 并行推进

- **操作**：首阶段通过且平台允许后，“继续” → 核对并发 → “继续所有”；验证 `deploying`，保存已继续凭据，此后不重复继续。
- **并行**：用户允许时，不同 app 可同时启动首批和观察；每 app 独立验收、独立放行。应用内并发与同时发布的 app 数分别控制，并检查应用间依赖。
- **停止**：持续异常、未知变更或他人操作时停止相关后续动作并报告，不自动回滚或恢复他人暂停。`paused` 先查日志区分检查点与人为暂停；停止自身动作不等于平台已暂停。

## 7. 全量验收

- **平台**：发布单 `finished`。
- **实例**：遍历全部分页，当前范围100%目标镜像、Running/healthy/up，摘要与表格一致；扩缩容记录新增/移除实例，不自行改容量。
- **监控**：最后一台也满足完整成熟窗口，全量样本有效。无旧版本接流时使用已保存的同期对照及基线，不复用旧残留时序。
- **结论**：分别记录平台完成、镜像生效、业务监控验收；缺一项则明确待验，不混称全部完成。

## 8. 进度与收尾

- 按授权渠道及频率发送启动、阶段、异常和最终报告，包含：app/e、目标版本、采集时间、平台状态、已升级/更新中/未升级数量、健康接流、监控窗口/覆盖、评估结果与缺口、下一步及 Caster链接。
- 企业微信 Markdown 每条≤4096 UTF-8字节；按报告标识和回执防重，仅 `errcode=0` 记成功。密钥留在仓库外，不写入技能或报告。
- 全量验收通过且最终报告送达后，停止本次监测。
