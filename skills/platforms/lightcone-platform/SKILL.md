# Lightcone 平台界面与结构（第一层）

本文件是平台结构说明。字段及栏目来自已有配置发布案例；不同套餐或页面版本可能存在差异。bin 版本选择界面尚无实证。

## 页面层级

| 页面 / 区域 | 结构及关联对象 | 展示内容 / 功能 |
| --- | --- | --- |
| 登录页 | 平台入口之前的认证页面 | 扫码或账号认证界面 |
| 服务收藏列表 | 服务 → 多个实验 | 服务名称；选中服务后的实验列表 |
| 实验列表 | 服务下的实验，存在常规 CPU+GPU 和 puregpu 等不同类型 | 实验标识、配置入口、操作人/时间、CPU/GPU app、Caster 链接、Moni 监控、日志、zone、实例数与实例调节入口；具体栏目依套餐而异 |
| 实验配置页 | 指定服务/实验的配置对象 | 模型名称、KFC 名称、CPU部署配置、GPU部署配置、保存及新配置发布入口 |
| 保存确认界面 | 当前编辑内容 | 保存前的配置确认信息 |
| 新配置发布差异界面 | 线上配置与待发布草稿 | 配置差异与确认/取消控件；差异左右方向以界面标注为准 |
| 发布执行界面 / 记录 | 一次具体发布任务 | 开始入口、触发信息、检查过程、步骤结果和整体状态；发布历史关联对应版本与差异 |
| 关联审批页面 | 发布流程关联的审批单 | 申请人、当前节点、审批中/已完结等流程状态；入口以当前发布提示为准 |

## 配置栏目与字段

| 栏目 / 字段 | 含义 / 表达 |
| --- | --- |
| CPU部署配置、GPU部署配置 | 同一实验中分别面向 CPU/GPU 的配置区块；不等同于实验类型 |
| 配置galaxy | 控制对应区块 Galaxy 配置的开关 |
| 额外gflags | 多行名称、类型、值；CPU/GPU 各自独立；类型控件包含 bool 等选项 |
| 模型名称、KFC名称 | 页面所载配置关联的模型及 KFC 标识 |
| GPU额外性能参数 | 组包大小、并发度、线程数等性能设置，具体字段以页面为准 |
| 保存 | 持久化当前配置草稿的功能入口 |
| 新配置发布 | 当前配置发布的功能入口；并非已验证的 bin 发布入口 |
| Caster app/link、zone、实例数 | 关联应用、部署区域及实例状态信息；可能显示 0/0 或没有实例信息 |

## 数据与状态语义

- 表单骨架和静态标题可能先于配置数据出现；页面短暂空值与成功返回的空配置是不同状态。
- 草稿配置、线上已发布配置、实例当前运行状态是不同对象。
- “更新成功”表示配置保存成功；“配置更新触发成功”表示发布触发；“配置部署检查中”表示检查未完成。
- “执行成功”可能出现在单步骤或整体发布记录中；两者层级不同。
- 平台发布检查状态与后续实例滚动更新状态可能不在同一时间完成。
- “驳回到申请人”可仍处于“审批中”；不等同审批流程已完结。重复发布提示可与未结束的关联审批单有关。
- 0/0 是当前实例数量信息，不表示从未发布。原工作流用户确认，Caster app/link、zone 与实例数同时出现可作为已初始化发布过的线索；它不表达当前版本是否已在实例运行。
- Lightcone 页面 server_id 标识平台对象，不是 Prometheus source_id。app、cmd、KFC 和模型是不同标识，监控页面的相应筛选参数也不同。

这里描述界面事实与含义，不规定筛选实验、编辑顺序、重试、跳过、并行发布或验收策略。
