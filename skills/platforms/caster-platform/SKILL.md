# Caster 平台操作方案（第一层，待实证）

当前仓库没有 Caster 的页面流程、API 或发布实例证据。以下是输入输出契约和现场发现方法，不是已验证的按钮操作指南。不要猜测平台 URL、认证方式、制品格式、任务状态名、灰度策略或回滚入口。

## 输入与只读发现

从本次上下文取得平台入口、应用/服务、环境/集群、目标动作、制品或版本、授权范围。先阅读当前环境浏览器技能（如 ego-browser）或已提供的官方工具说明；登录由用户完成。

在实际页面或正式文档中核实并记录：

| 能力 | 需确认的事实 | 输出 |
| --- | --- | --- |
| 定位应用 | 应用标识、环境/集群、运行实例归属 | 唯一目标及证据 |
| 识别制品 | 当前版本、目标版本、来源与可用性、平台实际支持的版本/摘要标识 | 当前 → 目标映射；未知项明确标注 |
| 准备变更 | 实际发布入口、参数、变更预览或等效版本比较、当前是否已有发布 | 可执行路径及完整差异；若不能确认则受阻 |
| 提交发布 | 操作会影响的实例/批次、真实提交动作及授权范围 | 本次任务标识、提交时间和受影响目标 |
| 观察部署 | 实际状态语义、整体完成条件、每批次/实例目标版本 | 最终状态、失败项、实例版本覆盖 |
| 关联监控 | 该服务的健康检查、错误率/QPS/延迟等实际指标和数据源 | 查询依据与观察结果；不套用其他服务的指标 |

## 执行动作

确认目标、真实路径、版本差异及部署完成条件后，执行调用方已授权的动作。创建草稿、提交发布、回滚都是独立写入动作，不能通过“探索”名义触发。历史授权不跨任务自动继承。

若只有只读需求，只返回查询证据。目标版本已运行时不重复发布；已有发布进行中时先辨别它与本次目标关系，不能盲目提交第二次。非本次变更不恢复也不夹带发布。

提交后只观察本次任务，并核对实例实际版本；点击成功不代表部署成功。失败、状态不明或超出约定窗口时返回阶段、证据和缺项，停止盲目重试；不默认回滚。

本层不依赖 Lightcone，也不决定跨平台顺序。将目标、实际操作路径、版本对应、任务状态、实例覆盖和未验证项返回场景层。没有现场访问或文档时，只能报告发现受阻，不能声称 Caster 发布已具备执行条件。
